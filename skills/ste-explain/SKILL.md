# ste-explain：按 STE 结构约束写中文解释

ASD-STE100（Simplified Technical English，下称 STE）是航空维修手册用的受控语言规范。本 skill 取它的结构规则写中文解释，默认取 80% 刻度。读者是不熟悉当前领域的工程师，读这段是为了做一个判断或执行一个动作。他一遍读不懂的句子要重写，不指望他回头再读。用户说明读者熟悉领域时，规则 9 只对新造的术语生效。

## 刻度

| 刻度 | 何时 | 内容 |
| --- | --- | --- |
| 80%（默认） | 解释代码、diff、CI 结果、设计结论、排查结论 | 十条规则全部执行，词汇不锁定：允许领域术语、英文术语、常用缩略语、「因为 / 所以」 |
| 100% | 用户说「严格」「100%」「完整 STE」，或文本是操作步骤、安全说明 | 十条之上追加六条 |

不向用户说明用了哪一档，除非用户问。

## 80% 规则

1. 一句只说一件事。
2. 一句不超过 45 字。
3. 主动语态，说清谁做了什么。不用双重否定。
4. 用动词，不用名词化：写「检查日志」，不写「对日志进行检查」。
5. 一词一义：同一个动作从头到尾用同一个词。跨句指代用名字，不用「它」「前者」。
6. 用具体数字和场景解释，不打比方。数字带单位；说变化时给改前与改后两个值。
7. 三步以上的顺序用编号清单，并列项用清单，比较与映射用表格。表格格子也算一句，超过 45 字就拆。同一清单里的项用同一种句型。
8. 一段一个主题，不超过六句，最重要的一句放段首。整篇的结论放第一段。
9. 术语首次出现给一句定义；圈内没有统一译法的保留英文。
10. 用技术评审会上能说出口的词。口水词、玩笑腔、空洞强调词、英文词的直译造词都不用，反面词表在 `references/banned-words.txt`。

## 100% 追加

1. 每条指令单独成句，用祈使句。
2. 不省略主语。
3. 不用缩略语，首次出现写全称。
4. 安全类内容先写后果，再写动作。
5. 每句都能对应到一条事实；推断单独成句并标注「推断」。
6. 有条件的指令，条件在前、动作在后，一句一个条件。

## 守则

高于所有规则。规则与守则冲突时守则赢。

1. 保留原文的不确定程度。「可能失败」不能变成「失败」，「有时」不能变成「总是」。
2. 不新增原文没有的原因、频率、机制。改写读起来更顺是因为补了一个原因，那就不是改写。
3. 代码、命令、标识符、报错原文不改。
4. 事实与推断分开标注。事实给文件行号或命令与输出摘录，推断说明「未验证，跑 X 可确认」。引用证据前核对它覆盖的版本、时间、范围与结论对不对得上，对不上就写出差距。
5. 清楚即止，不追求最短。为缩短而丢掉条件、例外、范围限定时，写两句。
6. 已经合规的文本只回「已合规」，原文一字不动：不拆句、不补术语定义、不换词。

## 图

三个以上相互作用的部件，或有顺序、状态变化，加一张 mermaid 图。一图一事，节点超过十二个拆成两张。箭头上带动词（发送、读取、重试）。图里的名字和正文完全一致。图下方一句话告诉读者从哪看起。图中文字同样遵守十条规则。用户点名要图就画，点名不要就不画。

## 英文输入

规则相同，另加三条：不用 phrasal verb（写 start 不写 spin up）；只用简单时态（写 we received 不写 we have received，带不确定程度的 may have failed 保留）；不用分号。

## 输出

默认只给解释或改写后的文本。不加前言，不列用了哪些规则，不加「还需要什么」的收尾。对话里的改写不跑脚本，也不提脚本。

用户说「看改动」「用了哪些规则」「改前改后」时，改为输出三列表：规则、改前、改后。表后一行写出故意没改的地方和原因。

## 与其他 skill 并存

- 翻译腔句式、文档结构若有对应 skill 则交给它，本 skill 不复述。
- 解释排查结论时，若当前仓库有证据图（文件名以 `-evidence-graph.yaml` 结尾），事实引用节点编号与 evidence 字段，不另写一遍；图上没有的内容一律标为推断。不要求 evidence-graph 安装。

## 脚本

`scripts/ste_check.py` 做三项确定性检查：句长超过 45 字、同一文档里同一组同义词出现两个以上、反面词。默认只提示，`--strict` 时有命中退出码 1，`--json` 给结构化输出。同义词组在 `references/synonyms.txt`，反面词表在 `references/banned-words.txt`，项目自己的行话表用 `--banned <文件>` 叠加。只在改写磁盘上的文件、或用户要求检查某个文件时跑，命中的句子按规则 2、5、10 改。对话里的改写不跑。

```bash
C="${CLAUDE_SKILL_DIR}/scripts/ste_check.py"
[ -f "$C" ] || C="$(claude plugin list --json 2>/dev/null | python3 -c 'import json, sys; print(next((p["installPath"] for p in json.load(sys.stdin) if p.get("id", "").startswith("ste-explain@") and p.get("enabled")), ""))' 2>/dev/null)/skills/ste-explain/scripts/ste_check.py"
[ -f "$C" ] || C=$(find ~/.claude/plugins ~/.claude/skills -name .trash -prune -o -path '*/ste-explain/scripts/ste_check.py' -print 2>/dev/null | head -1)
[ -f "$C" ] || echo "未找到 ste_check.py，确认 ste-explain 插件已安装"
python3 "$C" <文件>
```
