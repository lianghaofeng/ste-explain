# 前后对照

每组对应 rules.md 的一个编号。「改前」是工程场景里常见的写法，「改后」是按 80% 规则改写的结果。改后不新增事实。

## 1. 80% 规则

### R1 一句只说一件事

改前：该轮次因为雷达话题在 42 秒时断了约 3 秒导致代价地图没更新，所以规划器在原地重规划了 6 次，最后超时失败。

改后：雷达话题在第 42 秒断开约 3 秒。这 3 秒内代价地图没有更新。规划器在原地重规划 6 次后超时，任务失败。

### R2 一句不超过 N 字

改前：当参数服务器在节点启动之后才下发这组参数时，由于行为服务器在激活阶段已经读取过一次参数快照，这次下发不会生效，需要重启节点。

改后：参数服务器在节点启动之后才下发这组参数。行为服务器在激活阶段已经读过一次参数快照。这次下发不生效，要重启节点。

### R3 主动语态

改前：该文件会在构建结束后被清理。

改后：构建脚本在构建结束后删除该文件。

改前：不能说这个参数不起作用。

改后：这个参数起作用。

### R4 用动词

改前：对日志进行检查后，对配置进行了修改。

改后：检查日志后，修改了配置。

### R5 一词一义

改前：先检查雷达话题，再校验里程计，最后确认 TF 树。

改后：先检查雷达话题，再检查里程计，最后检查 TF 树。

改前：规划器先读代价地图，再读里程计。它每秒更新一次。

改后：规划器先读代价地图，再读里程计。代价地图每秒更新一次。

### R6 用数字和场景，不打比方

改前：局部代价地图像一张跟着机器人走的小地毯。

改后：局部代价地图是以机器人为中心、边长 6 米、每格 5 厘米的栅格，随机器人移动。

改前：改完之后延迟降低了 30%。

改后：P99 延迟从 260 ms 降到 182 ms。

### R7 序列用清单

改前：先拉取分支然后编译，编译完成后跑单元测试，通过之后再派发仿真。

改后：

1. 拉取分支。
2. 编译。
3. 运行单元测试。
4. 测试通过后派发仿真。

### R8 重点句放段首

改前：我们先看了日志，又对比了两轮的参数，还查了镜像的提交号，发现两轮用的镜像不同，所以结果不可比。

改后：两轮用的镜像不同，结果不可比。依据有三条：日志里的镜像 tag 不同，两轮参数一致，镜像提交号分别是 a1b2c3 与 d4e5f6。

### R9 术语首现定义

改前：这个问题出在 lookahead 上。

改后：这个问题出在 lookahead 上。lookahead 是路径跟踪时向前取参考点的距离，这里是 1.2 米。

### R11 成文交付物用书面语

改前：两条流都走 WS 端口 7998，也都发布到车上的 MQTT broker。

改后：两条数据流均经 WebSocket 端口 7998 推送，并同时发布至机器人本机的 MQTT broker。

改前：`mapping_top_sdk` 的 HTTP 搬到 7999，调用方要跟着改。

改后：`mapping_top_sdk` 的 HTTP 服务迁移至 7999 后，调用方需同步修改。

改前（画板判断框）：是 5 的倍数吗

改后（画板判断框）：是否为 5 的倍数

改后没有写成「对调用方进行同步修改」：书面语靠标准动词，不靠名词化。

## 2. 守则优先

### G1 保留不确定程度

改前：这次失败可能是镜像没有命中缓存，重新打了一次镜像。

错误改法：这次失败是镜像没有命中缓存。

正确改法：这次失败可能是镜像没有命中缓存。日志显示镜像重新打了一次。

错误改法更短，但把「可能」删掉了，说的是另一件事。

### G2 不新增原因

改前：该请求可能失败了，原因可能是数据格式不匹配。

错误改法：该请求失败了。最常见的原因是客户端版本过旧。

正确改法：该请求可能失败了。可能的原因是数据格式不匹配。

错误改法加了「最常见」和「客户端版本过旧」，原文都没有。

### G4 事实与推断分开

改前：参数下发失败是因为目标节点没起来。

改后：参数下发失败，日志第 118 行是 `target node not available`。目标节点没有启动是推断，未验证，跑 `ros2 node list` 可确认。

### G6 已合规不硬改

输入：雷达话题在第 42 秒断开约 3 秒。这 3 秒内代价地图没有更新。

输出：已合规。

## 3. 英文输入

改前：Once the upstream job has completed and assuming no errors were raised, the downstream agent should proceed to consume the output artifact; partial artifacts are sometimes produced under timeout conditions.

改后：Wait for the upstream job to finish with no errors. Then read the output artifact. A timeout can produce a partial artifact.

用到的规则：R1 拆句，E2 去掉 has completed，E3 去掉分号，E1 把 proceed to consume 换成 read。G2：原文没有说「检查产物是否完整」，改后也不加。
